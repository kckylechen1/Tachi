## Fix for #1591/#1592 blocker: tachi_staff(start) bypasses the staffing-reason gate

This is a security-critical fix to the Staff contract. Per AGENTS.md hard-guard: minimal change, RED-before/green-after discrimination test, independent different-vendor review. The user's 6 requirements are the frozen contract.

### Branch strategy
- New fix branch off `origin/main` (which has #1587 + #1589 merged + the unrelated #1590). NOT off my old PR3/PR4 branches — those are stale and stacked on the wrong base. Rebuild the Staff contract cleanly on current main.
- This single fix supersedes/rebases BOTH #1591 and #1592 (they're blocked on this exact defect). After the fix lands, the downstream PRs (#1593–#1597) get rebased onto it.

### Architecture decisions (confirmed with user)
- **Two-layer gate**: facade-level (staff_start validates the typed reason → clear model-facing error) + kernel-level fail-closed (handle_tachi_dispatch rejects a missing staffing_reason → catches any future bypass). Belt-and-suspenders, matches the existing #894 authority-gate defense-in-depth pattern.
- **Delete all 6 marker fields** (boundary_reason, routing_trigger, routing_override, assignment_mode, scope, completion). Keep ONLY a typed `staffing_reason`. Reuse the EXISTING `TachiDispatchReason` enum (ExplicitUserRequest | DurableCrossSession | CrossDeviceRemote | NativeSubagentUnavailable) — do not invent a new vocabulary.

### Concrete changes

**1. `TachiDispatchParams` gets a new required field** (`crates/tachi-params/src/facade/dispatch.rs`):
```rust
/// #1319-E1 admission contract: the typed reason execution is leaving the
/// host harness. REQUIRED for tachi_staff(start); the kernel fails closed
/// without it. Mirrors TachiTaskParams.dispatch_reason so the vocabulary
/// cannot drift. Stamped into the canonical receipt (status.json).
pub staffing_reason: TachiDispatchReason,
```
Non-optional (required). This forces every `TachiDispatchParams { ... }` literal to declare a reason — compile-error-driven audit of all callers (staff_start, task_router dispatch arm, arena spawn, poke probes, test helpers). Each caller must supply a valid typed reason.

**2. `StaffStartRequest`** (`crates/tachi-server/src/staffing_ops/mod.rs`) — replace the 6 marker fields + add the typed reason:
```rust
pub(crate) struct StaffStartRequest {
    pub task: String,
    /// REQUIRED typed reason. Admission fails closed without it.
    pub staffing_reason: TachiDispatchReason,
    // (profile, worker, project, stage, issue_ref, pr_ref, flow_id unchanged)
    // DELETE: scope, assignment_mode, boundary_reason, routing_trigger, routing_override, completion
}
```
`into_params()` now maps `staffing_reason` through to `TachiDispatchParams.staffing_reason` (instead of dropping it). The `#[allow(dead_code)]` attrs on the deleted fields are removed.

**3. `StaffStartFields`** (`crates/tachi-params/src/facade/orchestration.rs`) — mirror: delete the 6 marker fields, add `pub staffing_reason: TachiDispatchReason` (required, no `#[serde(default)]` — it MUST be supplied on the wire).

**4. Facade gate** — `staff_start` validates BEFORE calling the kernel:
```rust
pub(crate) async fn staff_start(server, request) -> Result<String, String> {
    // Facade-level admission: a typed staffing_reason is mandatory. This
    // mirrors require_tachi_dispatch_reason's fail-closed shape. The error
    // names the native-first policy so the model sees WHY it was rejected.
    // (staffing_reason is non-optional on the struct, so a missing field is
    // rejected at deserialization; this fn documents the policy at the call
    // site and is where a future policy decision would land.)
    let params = request.into_params(); // carries staffing_reason into TachiDispatchParams
    handle_tachi_dispatch(server, params).await
}
```
Because `staffing_reason` is non-optional, the gate is structural (serde rejects a missing field before this fn even runs). The facade route's only remaining validation is the non-empty `task` check.

**5. Kernel fail-closed gate** — inside `handle_tachi_dispatch` (`dispatch_ops/dispatch.rs`), before the first `write_status_json` (line ~395), AFTER the existing authority gate:
```rust
// #1319-E1 fail-closed staffing-reason gate. staffing_reason is non-optional
// on TachiDispatchParams, so a well-typed caller always carries one — but
// this defense-in-depth check ensures NO caller (internal, operator, or a
// future facade) can reach the receipt-first seed without a typed reason.
// It runs before step 0's write_status_json, so a rejection creates ZERO
// run directory / status.json / trajectory artifacts.
```
Since the field is non-optional, this check is structurally always-true for compiled callers — but it documents the invariant and guards against `unsafe`/reflection/future-loophole paths. (If the user prefers this to be a runtime `match` that rejects `None`, that requires the field to be `Option<TachiDispatchReason>` — but the user chose required, so the compile-time guarantee is stronger.)

**6. Receipt stamp** (requirement #4) — add to BOTH `write_status_json` `extra` blocks (lines ~425 and ~517):
```rust
"staffing_reason": serde_json::to_value(&params.staffing_reason).unwrap_or(Value::Null),
```
This persists the effective reason into canonical status.json, making staffing auditable. (Alongside the existing `"authority"` stamp.)

**7. explicit_user_request is an override, not authority** (requirement #5) — the `TachiDispatchReason::ExplicitUserRequest` variant's doc comment already says "explicit user request"; add a clarifying note to the enum doc that this variant is a recorded override, not a self-granted authority elevation (it is stamped into the receipt for audit, not used to bypass the authority gate). No behavioral change — the authority gate (`compile_dispatch_contract`) is independent and still applies.
