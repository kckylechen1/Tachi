**Headlines:**

1. **No worker has run for 7 of the largest project DBs** (`hapi`, `wiki`, `quant`,
   `openclaw`, `sigil`, `tachi`, `jayne`). Root cause is architectural: the
   foundry runtime is a single in-process producer/consumer pipeline keyed off
   one (global, project) pair. Nothing iterates `manifest.dbs`. See
   `crates/memory-server/src/main.rs:476-595` and
   `crates/memory-server/src/foundry_runtime_ops/maintenance.rs`. → fixed in **PR-4**.
2. **`source` and `category` columns accept free-form strings** ("Quant Analyzer
   Memory Integration", "session_note", …). 13 distinct illegal values found
   across 7 DBs. → fixed in **PR-1** (Rust enum + SQLite CHECK + normalizer).
3. **`/handoff`, `/kanban`, `/wiki` rows have `retention_policy = NULL`** in
   every Global DB. Default GC will sweep them. → fixed in **PR-1** + **PR-5**
   (write-site default + repair).
4. **Project DBs are absorbing each other's content**: 89 `/hapi/` rows in
   antigravity, 13 kanban rows in antigravity, 50 cross-project rows in
   openclaw, 3 wiki rows in global, 230 hapi rows mis-stamped to antigravity's
   db_path. Path-prefix routing is not enforced on write. → fixed in **PR-3**
   (write-site router) + **PR-5** (repair re-routes existing rows).
5. **Manifest holds duplicate logical DBs**: `wiki/memory.db` is a symlink to
   `wiki/.tachi/memory.db`; `~/.openclaw/agents/yaya/...` is a symlink alias of
   `~/Desktop/...`; 4 `tmp/feature-daemon-global.db` byte-identical scaffolds.
   → fixed in **PR-2** (canonicalize + dedupe) + **PR-5** (manifest rewrite).
6. **3 processes are concurrently holding `~/.tachi/global/memory.db`** (PIDs
   40173, 45160, 69893). Multi-writer race hazard. → fixed in **PR-4** (single
   PID lock for daemon).
7. **5 OpenClaw legacy `chunks` schema DBs are mis-classified as `schema_kind:
   tachi`**. `researcher.sqlite` has 220 chunks reported as 0 mem. → fixed in
   **PR-2** (classifier reads `chunks` table presence).
8. **6/7 large DBs have FTS drift**, including `quant` whose `memories_fts`
   virtual table is gone entirely. → fixed in **PR-1** (write-trigger audit) +
   **PR-5** (FTS rebuild).

## Bugs (must fix in code)

### B1 — `source` enum unenforced
- **Severity**: HIGH
- **Evidence**: `global` has `source = "Quant Analyzer Memory Integration"`,
  antigravity has `"Memory MCP Runtime Verified"`, sigil has prose values, wiki
  has historical-only `wiki_batch_inject` (1992 rows) /
  `tachi_knowledge_merge` (626).
- **Canonical enum**: see `docs/audit-2026-04-30.md` companion code change.
  Observed valid: `manual, mcp, cli, agent, extraction, clawdoctor,
  capture_session, compact_session_memory, bracket_self_evolution,
  foundry_distill, foundry_agent_evolution, distill_trajectory,
  skill_quality_guard`.
- **Fix (PR-1)**: introduce `MemorySource` Rust enum with `as_str` + `parse`,
  validate at every write site (`memory_search_ops.rs:95`, `kanban.rs:515`,
  `handoff_ops.rs:90`, etc.), add SQLite CHECK constraint via migration. Old
  rows get a normalization pass.

### B2 — `category` enum unenforced
- **Severity**: HIGH
- **Evidence**: jayne-ext has `session_note`, `reflection`; global has
  `handoff` as a category. Documented set is `fact|decision|experience|
  preference|entity|other` (+ `kanban` extension).
- **Fix (PR-1)**: `MemoryCategory` enum + write-site validation + CHECK
  constraint with normalizer migration.

### B3 — `scope` value contamination
- **Severity**: HIGH
- **Evidence**: main-agent DB has 51 rows with `scope` set to `self`,
  `other_agent:jayne`, `other_agent:openclaw`. Documented set is `user |
  project | general`.
- **Fix (PR-1)**: enum + CHECK; existing illegal values fold to `general` with
  a recorded note in `metadata.audit.scope_normalized_from`.

### B4 — write-site path routing not enforced
- **Severity**: HIGH
- **Evidence**:
  - antigravity holds 13 `/kanban/...` and 89 `/hapi/...` rows
  - hapi-project holds 7 `/kanban/...` rows
  - openclaw-project holds rows under `/sigil/`, `/tachi/`, `/hapi/`, `/nexu/`
  - global holds 3 `/wiki/` and 10 cross-project rows
- **Rule** (per yardstick): `/handoff` and `/kanban/...` MUST live in Global;
  `/wiki/...` lives wherever the WIKI is for that knowledge domain (typically
  the `wiki` named project or a project DB explicitly opted-in).
- **Fix (PR-3)**: at every write site, classify the path prefix and route to
  the correct `DbScope`. If routing fails (caller passed
  `project=Some("antigravity")` for a `/kanban/...` write), reject with a
  typed error.

### B5 — system rows written with `retention_policy = NULL`
- **Severity**: HIGH (data loss risk)
- **Evidence**: every `/handoff`, `/kanban/...`, `/wiki/...`,
  `source='foundry_distill'` row in every audited Global / wiki / agent DB has
  `retention_policy = NULL` ≡ `durable`. Default `archive_stale_memories` will
  archive them.
- **Fix (PR-1)**:
  - `/handoff` writes (`handoff_ops.rs:90`) → default `pinned`
  - `/kanban/...` writes (`kanban.rs:515`) → default `pinned`
  - `/wiki/...` writes (`copilot_ops.rs`) → default `permanent`
  - `source='foundry_distill'` writes (`foundry_runtime_ops/maintenance.rs`)
  - `/wiki/...` writes (`wiki_ops.rs`) → default `permanent`
  - `source='foundry_distill'` writes (`foundry_runtime_ops/.../mod.rs:16`)docs/storage-audit-2026-04-30
    → default `permanent`
- **Repair (PR-5)**: backfill NULL → correct policy on existing rows that
  match those criteria.

### B6 — migration / rescue / split tools don't re-stamp `provenance.db_path`
- **Severity**: MED (not corrupting, but confuses audit)
- **Evidence**: 230 hapi-project rows still report `provenance.db_path =
  …/antigravity/memory.db` from the antigravity-split exercise. wiki has 49
  rows leaking `Quant_Analyzer_2026` provenance. main-agent has 60 with legacy
  `memory-hybrid-bridge` provenance.
- **Fix (PR-3)**: every code path that copies/migrates rows between DBs MUST
  call `provenance::reinject_for_destination(row, dest_db_path)`. Tag
  `metadata.provenance.migrated_from` for traceability.
- **Repair (PR-5)**: walk all DBs, compare `provenance.db_path` to actual
  file, restamp mismatches and record original under
  `metadata.provenance.migrated_from`.

### B7 — manifest scanner doesn't canonicalize paths
- **Severity**: HIGH (causes phantom DBs in `tachi status`/`doctor`)
- **Evidence**: `~/.tachi/projects/wiki/memory.db` is a 55-byte symlink to
  `~/.tachi/projects/wiki/.tachi/memory.db`; manifest registers both as
  separate `dbs[]` entries. Also: `~/.openclaw/agents/yaya/...` is a symlink
  alias of `~/Desktop/...`, every desktop DB is double-registered.
- **Fix (PR-2)**: `Manifest::populate_from_doctor` and manifest GC call
  `path.canonicalize()` first; on
- **Fix (PR-2)**: `Manifest::insert` calls `path.canonicalize()` first; ondocs/storage-audit-2026-04-30
  duplicate canonical, merge entries (newer `last_doctor_at` wins). Refresh
  also collapses existing duplicates.

### B8 — manifest classifier mis-tags OpenClaw legacy `chunks` schema as `schema_kind: tachi`
- **Severity**: HIGH (status & doctor under-report content)
- **Evidence**: `~/.openclaw/memory/researcher.sqlite` (220 chunks),
  `ops.sqlite` (224 chunks) reported as 0 memories. Classifier checks for
  `memories` table only.
- **Fix (PR-2)**: schema classification checks for a legacy `chunks` table when
  canonical `memories` columns are absent → `schema_kind: openclaw_legacy`.
- **Fix (PR-2)**: classifier in `manifest.rs` checks for `chunks` table when
  `memories` is absent → `schema_kind: openclaw_legacy`.docs/storage-audit-2026-04-30
- **Repair (PR-5)**: re-classify existing manifest entries, archive truly
  empty ones, leave non-empty for explicit migration.

### B9 — FTS triggers unreliable
- **Severity**: HIGH (search broken)
- **Evidence**: hapi-project drift +569 (half the index stale), tachi-project
  +47/73 (64 %), openclaw +50, sigil +43, antigravity +32, global +5,
  main-agent −1, hapi-agent −12. quant project DB has lost the
  `memories_fts` virtual table entirely.
- **Fix (PR-1 audit, PR-5 rebuild)**: write a `verify_and_rebuild_fts(conn)`
  helper; have foundry maintenance worker call it periodically. PR-5 runs
  it once across every DB.

### B10 — no daemon singleton lock; multiple writers race for global
- **Severity**: HIGH (corruption risk under load)
- **Evidence**: `lsof` shows 3 PIDs holding `~/.tachi/global/memory.db`
  (40173 antigravity tachi, 45160 hyperion memory-server, 69893 bare tachi).
  WAL/SHM file races confirmed in earlier sessions.
- **Fix (PR-4)**: PID lock file at `~/.tachi/daemon.lock` with
  `flock`-style claim. Daemon refuses to start if another holds it; CLI
  short-lived writes acquire transient locks via existing
  `db_path_held_by_other_process()` as a short-lived write guard.
- **Fix (PR-4)**: PID lock file at `~/.tachi/global/.tachi.daemon.pid` with
  `flock`-style claim. Daemon refuses to start if another holds it; CLI
  short-lived writes acquire transient locks via existing
  `db_path_held_by_other_process()` (see `bootstrap.rs:2086,2200-2240`).docs/storage-audit-2026-04-30

### B11 — older DBs missing modern tables
- **Severity**: MED
- **Evidence**: `projects/openclaw`, `projects/tachi`, `agents/researcher`
  lack `foundry_jobs`, `domains`, `hub_capabilities`, `audit_log`. Created by
  earlier binary, never re-opened by current.
- **Fix (PR-2)**: every `MemoryStore::open` calls `ensure_all_tables(conn)`
  (apply missing migrations idempotently). Add a `tachi doctor --upgrade`
  flag for explicit one-shot.

### B12 — manifest auto-pickup includes throwaway scaffolds
- **Severity**: MED
- **Evidence**: 4 byte-identical `tmp/feature-daemon-global.db` files
  (vitejs/vite zread fixture) registered as live DBs.
- **Fix (PR-2)**: manifest discovery skips paths matching `**/tmp/**`,
  `**/test-fixtures/**`, `**/.git/**`. Configurable allowlist for power users.

### B13 — historic `source` strings linger in wiki DB
- **Severity**: LOW (read-only legacy)
- **Evidence**: 1992 `wiki_batch_inject`, 626 `tachi_knowledge_merge`,
  `zread:get_repo_structure`. None of these are produced by current code.
- **Fix (PR-1 normalizer)**: map known historicals to canonical equivalents
  (e.g. `wiki_batch_inject` → `manual` with `metadata.audit.legacy_source`
  preserved).
