# Tachi 工具面 v2 设计 — 2026-05-01 设计会议沉淀

## 背景
从 Tachi MCP 工具面 UX 审查出发，经 Oracle (GPT-5.5) 和 Claude 两轮审查，结合 acpx (OpenClaw ACP client) 的编排能力，形成完整的工具面 + 调度 + 进化闭环设计。

## 核心原则
1. **Profiles 编码权限等级，不是 agent 品牌** — Claude 的关键洞察
2. **Facade 为主，底层为逃生舱** — 不暴露重复入口，避免路由歧义
3. **Skills 是注入的上下文，不是独立调用** — dispatch 自动装配 skill，但主 agent 保留手动查看/执行能力
4. **7 个工具是甜点，10 个是上限** — LLM 选择准确度在 10-15 工具后急剧退化

## Profile 架构（3+1 层）

### `standard`（主 agent / IDE — Windsurf, Cursor, Antigravity, Trae, CLI standalone）
10 个工具：

| # | 工具 | 作用 |
|---|------|------|
| 1 | `tachi_search` | 统一搜索 wiki + memory（scope: wiki/memory/all） |
| 2 | `tachi_save` | 统一写入 wiki/memory/note（含 id 支持 update） |
| 3 | `tachi_browse` | 浏览 wiki 分类 |
| 4 | `tachi_handoff` | 统一交接（action: leave/check） |
| 5 | `tachi_plan` | 任务规划（含 route_recommend + skill 推荐 + context 聚合） |
| 6 | `tachi_dispatch` | 调度 agent（ACP + git worktree + skill 注入）【待实现】 |
| 7 | `hub_discover` | 手动查看 skill/capability |
| 8 | `run_skill` | 手动执行 skill |
| 9 | `recall_context` | 手动拉取任务上下文 |
| 10 | `web_search` | 外部网络搜索【待实现/挂载】 |

### `delegate`（被调度的 worker agent — Claude Code, Codex, ACP worker）
6 个工具：

| # | 工具 | 作用 |
|---|------|------|
| 1 | `tachi_search` | 搜索 |
| 2 | `tachi_save` | 写入（可选，看权限） |
| 3 | `tachi_browse` | 浏览 wiki |
| 4 | `tachi_unstick` | 自救解卡（delegate 专属） |
| 5 | `run_skill` | 执行被注入/推荐的 skill |
| 6 | `web_search` | 网络搜索 |

delegate 不给：`tachi_dispatch`（防递归）、`tachi_handoff`（不负责跨 session）、`hub_discover`（skill 由主 agent 选）

### `operate`（OpenClaw, Hermes 等 agent framework）
现有 operate bundle 不变，~30+ 工具。

### `admin` — 全量 ~110 工具，调试/管理用。

## tachi_dispatch + task_completed 闭环

### 调度流程
```
tachi_plan("重构 auth 模块")
  → 搜 wiki/memory → 相关教训和上下文
  → route_recommend → "Claude Code 适合，预计 5min"
  → 推荐 skills → [gastown, superpowers]
  ↓
tachi_dispatch(agent="claude", task="...", isolation="worktree")
  → 创建 git worktree
  → 自动注入 skills + wiki 教训 + memory 上下文
  → 通过 ACP 协议 dispatch（不是 MCP PTY scraping）
  → 实时 progress 跟踪
  ↓
delegate agent 执行（带 tachi_unstick 自救能力）
  ↓
task_completed → 类似 GitHub merge
  → 主 agent 审批 / 自动审批
  → git merge worktree 回主分支
  → eval_ledger 记录（耗时/cost/质量/agent/skill）
  → 后台 worker 自动触发：
    1. distill_trajectory → 从轨迹提炼可复用 Skill
    2. skill_evolve → 达到阈值时自动进化 skill prompt
    3. tachi_save → 沉淀执行教训到 wiki/memory
```

### Skill 进化管线（已实现，需接入自动触发）
```
task_completed
  → distill_trajectory(task, execution_trace, outcome)
    → 生成 skill snapshot + 注册到 Hub
  → skill_evolve(skill_id, feedback)
    → 分析遥测 + LLM 改进 → 新版本 capability
  → synthesize_agent_evolution
    → 更高层 agent profile 演化提案
```

## 设计决策记录

### Oracle (GPT-5.5) vs Claude 审查对比
| 问题 | Oracle | Claude | 最终采纳 |
|------|--------|--------|----------|
| Profile 数量 | 5 个 | 3 个 | 4 个（standard/delegate/operate/admin） |
| CLI vs IDE | 分开 | 合并 | 合并为 standard |
| subagent | 单独 read-only | 删掉 | 改为 delegate（带 unstick） |
| 命名 | 品牌名 | 权限名 | 权限名 |
| Facade escape hatch | facade only | facade + raw | 底层保留在 operate/admin |
| run_skill in IDE | 不要 | dispatch 消化 | 保留（主 agent 要看 skill） |
| get_memory | 需要 | 验证后不需要 | search 已返回全文，不需要 |

### 关键引用
- acpx: https://github.com/openclaw/acpx — ACP headless client，启发了 tachi_dispatch 设计
- ACP vs MCP: MCP 是工具协议（请求-响应），ACP 是 agent 会话协议（持久、多轮、可取消）。dispatch agent 用 ACP 更自然
- LLM 工具选择退化: 10-15 工具后准确度急剧下降（Claude 引用的研究）
