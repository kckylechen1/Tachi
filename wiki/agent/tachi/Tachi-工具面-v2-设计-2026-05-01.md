# Tachi 工具面 v2 设计 — 2026-05-01 设计会议沉淀

## 背景
从 Tachi MCP 工具面 UX 审查出发，经 Oracle (GPT-5.5) 和 Claude 两轮审查，结合 acpx (OpenClaw ACP client) 的编排能力，形成完整的工具面 + 调度 + 进化闭环设计。

## 核心原则
1. **Profiles 编码权限等级，不是 agent 品牌** — Claude 的关键洞察
2. **Facade 为主，底层为逃生舱** — 不暴露重复入口，避免路由歧义
3. **Skills 是注入的上下文，不是独立调用** — dispatch 自动装配 skill，但主 agent 保留手动查看/执行能力
4. **7 个工具是甜点，10 个是上限** — LLM 选择准确度在 10-15 工具后急剧退化

## 架构分层

Tachi 不重新实现 ACP session runtime。tachi_dispatch 初期以 subprocess/NDJSON 方式调用 acpx；Tachi 负责 context/skill/sandbox/worktree/eval 编排，acpx 负责 agent session、queue、cancel、stream。

```
┌──────────────────────────────────────────────────────────┐
│  Tachi = Context / Memory / Skill / Control plane        │
│    - Profile (工具可见性)                                 │
│    - Sandbox (数据访问边界)                               │
│    - tachi_plan / tachi_dispatch / task_completed         │
│    - eval_ledger / skill_evolve / distill_trajectory      │
├──────────────────────────────────────────────────────────┤
│  acpx = Agent session / runtime plane                    │
│    - ACP protocol adapter (codex/claude/pi/gemini/...)   │
│    - Session lifecycle, queue, cancel, stream, auth      │
│    - Permission model (--approve-reads/all/deny)         │
├──────────────────────────────────────────────────────────┤
│  git worktree = Isolation plane                          │
│    - 每个 dispatch 一个 worktree，避免 agent 互踩         │
│    - merge 由 task_completed 后的 approve_merge 完成     │
└──────────────────────────────────────────────────────────┘
```

## 三层权限模型

delegate profile **不是** sandbox。三层各管各的，缺一不可：

| 层 | 控制什么 | 归属 | 状态 |
|----|---------|------|------|
| **Profile** | 工具可见性 | Tachi `profiles.rs` | ✅ 已实现 (standard/delegate) |
| **Tachi Sandbox** | memory/wiki/path 数据访问 | Tachi `sandbox_set_policy` | ✅ 已有 |
| **acpx Permissions** | 文件系统 + shell 操作权限 | acpx `--approve-*` | ✅ acpx 已有 |

`tachi_dispatch` 在派发 delegate 时同时配置三层。

## tachi_dispatch + task_completed 闭环

### 调度流程
```
tachi_plan("重构 auth 模块")
  → 搜 wiki/memory → 相关教训和上下文
  → route_recommend → "Claude Code 适合，预计 5min"
  → 推荐 skills → [gastown, superpowers]
  ↓
tachi_dispatch(agent="claude", task="...", isolation="worktree")
  → ① 创建/复用 git worktree
  → ② 设 Tachi sandbox policy (delegate 数据访问范围)
  → ③ 组装 prompt (task + skills + wiki 教训 + memory 上下文)
  → ④ subprocess: acpx <agent> --format json --cwd <worktree> [--approve-reads] "prompt"
  → ⑤ 解析 NDJSON stream → 实时 progress
  → ⑥ 持久化 trajectory 到 memory
  ↓
delegate agent 执行（带 tachi_unstick 自救能力）
  ↓
task_completed (= GitHub PR ready，不等于 merge)
  → 冻结结果 + 收集 diff/tests/logs
  → eval_ledger 记录（耗时/cost/质量/agent/skill/outcome）
  → 后台 worker 入队：distill_trajectory → skill_evolve
  → 返回 review bundle，等待 approve_merge
  ↓
approve_merge / task_merge （显式动作，不自动）
  → git merge worktree → 主分支
  → cleanup worktree + session
  → tachi_save 沉淀执行教训到 wiki/memory
```

**关键：`task_completed` ≠ merge。** delegate 只能声明完成；Tachi 记录结果、收集 diff、跑验证；主 agent 或 policy 决定 merge。

### Skill 进化管线（已实现，需接入自动触发）
```
task_completed
  → distill_trajectory(task, execution_trace, outcome)
    → 生成 skill snapshot + 注册到 Hub
  → skill_evolve(skill_id, feedback)
    → 分析遥测 + LLM 改进 → 新版本 capability
  → synthesize_agent_evolution
    → 更高层 agent profile 演化提案
```

## 设计决策记录

### Oracle (GPT-5.5) vs Claude 审查对比
| 问题 | Oracle | Claude | 最终采纳 |
|------|--------|--------|----------|
| Profile 数量 | 5 个 | 3 个 | 4 个（standard/delegate/operate/admin） |
| CLI vs IDE | 分开 | 合并 | 合并为 standard |
| subagent | 单独 read-only | 删掉 | 改为 delegate（带 unstick） |
| 命名 | 品牌名 | 权限名 | 权限名 |
| Facade escape hatch | facade only | facade + raw | 底层保留在 operate/admin |
| run_skill in IDE | 不要 | dispatch 消化 | 保留（主 agent 要看 skill） |
| get_memory | 需要 | 验证后不需要 | search 已返回全文，不需要 |

### 关键引用
- acpx: https://github.com/openclaw/acpx — ACP headless client，启发了 tachi_dispatch 设计
- ACP vs MCP: MCP 是工具协议（请求-响应），ACP 是 agent 会话协议（持久、多轮、可取消）。dispatch agent 用 ACP 更自然
- LLM 工具选择退化: 10-15 工具后准确度急剧下降（Claude 引用的研究）

## 实现路线图（MVP 顺序）

1. **eval_ledger schema + tool** — 最底层数据基础。先用 memory entry (path=/eval/*)，后续可抽到专表。
2. **task_completed facade** — delegate 声明完成时调用；写 eval_ledger、入队 distill/evolve、返回 review bundle。
3. **tachi_dispatch MVP** — subprocess 调 acpx (不走 ACP native)，prompt 组装，stream 解析。先不做 worktree。
4. **worktree isolation** — 每个 dispatch 一个 worktree；approve_merge 合并。
5. **后台 worker 自动触发** — task_completed 入队后台 pipeline (distill_trajectory → skill_evolve)。
6. **route_recommend 融入 tachi_plan** — 基于 eval_ledger 的历史数据给路由建议。

这个顺序保证每一步都有数据落点，不会做到一半回头改。
